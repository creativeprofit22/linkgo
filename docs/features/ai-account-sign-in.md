# AI account sign-in (OpenAI and Anthropic)

Linkgo can connect OpenAI and Anthropic with **account sign-in** (OAuth 2.0 authorization code + PKCE) as well as with API keys. This page records the per-provider decision required before implementation, and how the flow works.

### How the decision is enforced

- Both providers show an **Account sign-in** option in Connected accounts, but **Sign in with {provider} account** stays disabled until the operator ticks the acknowledgement: "I understand the risk to my {provider} account and will use this for personal use only".
- The native command `linkgo_auth_oauth_start` rejects OpenAI/Anthropic unless `acknowledgeTermsRisk: true` is sent. The renderer cannot skip the check.
- The existing API-key flow is unchanged, including pasted Anthropic `sk-ant-oat` tokens.
- If the provider rejects a live call (for example Anthropic answering that the credential is only authorized for Claude Code), that result is recorded as a scoped exclusion in `docs/verification/ai-account-sign-in.md`. It is never reported as verified.

### Risks the operator accepts

- The provider may suspend or restrict the operator's ChatGPT/Claude account for third-party use.
- The private Codex endpoint, the `originator` rules or Anthropic's identity checks can change without notice and break sign-in.
- Port 1455 is shared with the Codex CLI. If it is busy, Linkgo falls back to pasting the callback URL.

## Flow

1. Operator opens the provider in Connected accounts, picks **Account sign-in**, ticks the acknowledgement and presses **Sign in with {provider} account**.
2. Native code creates PKCE (S256) and a random state, stores them in a 10-minute pending session, and returns only the authorization URL. Native code also opens that URL in the default browser (`auth::external_browser`: https-only allowlist of the exact OpenAI, Anthropic and LinkedIn authorize endpoints, launched with an argument array, no shell) and reports `browserOpened`. The WebView never opens `target="_blank"` links itself: every window's native new-window handler denies them and hands only https links on `www.linkedin.com`/`linkedin.com` to the default browser (`open_external_url`), so sign-in pages on other hosts would be dropped and the UI shows a copy-link fallback instead of a link.
3. OpenAI: a loopback listener on `127.0.0.1:1455` waits up to 5 minutes for `GET /auth/callback`. It checks `state`, exchanges the code, saves the tokens and emits `linkgo://auth-progress` `auth_done`. If the port is busy, or the browser is elsewhere, the operator pastes the full callback URL instead.
   Anthropic: the operator pastes the `code#state` shown on Anthropic's callback page. The Anthropic authorize URL and state mirror gg-core's `loginAnthropic` exactly: same parameter order, `URLSearchParams` form encoding (`+` for spaces) and a 16-byte **hex** state (32 chars). claude.ai rejects the shared 22-char base64url CSRF state with "Authorization failed / Invalid request format".
   The `claude-cli/<version> (external, cli)` User-Agent sent to Anthropic's token endpoint and Messages API ports gg-core's `getClaudeCliUserAgent` (`auth::claude_code_version`): the version comes from the npm registry (`@anthropic-ai/claude-code/latest`, 3 s timeout), cached for 24 h in memory and in `claude-code-version.json` under app data. If npm is unreachable it uses the stale disk cache, then the built-in fallback `2.1.280`, and retries npm after 5 minutes. Only plain version tokens are accepted, because the value becomes an HTTP header. It also ports gg-core's `noteRequiredClaudeCodeVersion` recovery path. When a signed-in Anthropic call fails with "version X or newer is required" (Anthropic gates new models on a minimum client version), Linkgo picks the npm latest version if it is newer than X, otherwise X. If that target is newer than the cached version, Linkgo writes it to the memory and disk caches (24 h), rebuilds the User-Agent and retries the call exactly once. Other failures are not retried.
4. Tokens are saved in the identifier-scoped OS keyring. Large payloads are split across several keyring entries because Windows Credential Manager limits each entry to 2560 bytes.
5. Before each agent run and each status check, native code refreshes a token that expires within 5 minutes. Refresh is serialized per provider, so concurrent runs cannot race and burn a rotating refresh token. The renderer therefore treats an OpenAI/Anthropic sign-in with status `expired` as ready for agent runs, and the card shows **Renews next time it's used** instead of asking to reconnect. `reauth_required` stays blocked.
6. If the provider rejects the refresh (4xx), tokens are cleared and the card shows **Sign in again** (the connect dialog says "Reconnect needed: sign in again to keep using {provider}."). Network or 5xx errors keep the tokens and report the error.
7. **Sign out** deletes the credential. Signing in replaces a saved API key for the same provider (after confirmation), and saving an API key replaces a sign-in.

Tokens never reach the renderer: IPC carries only the authorization URL, state, account label, scopes, expiry and status.
