## Source findings — standards and correctness

Line references identify the source inspected during this audit and may move after edits. Recommended fixes are proposals, not completed work.

### F1 — High: remote publishing and local recording are separate

**Confirmed code gap:** the native post command sends the LinkedIn request and returns its result. The approval dialog then records success through a separate callback. It explicitly handles the case where publishing succeeded but local recording failed.

**Risk requiring fault-injection verification:** closing the app or failing the local write between these operations can leave a live post without a successful local record. Retrying may duplicate the external action. No duplicate live post was created or observed during this audit.

**Recommended fix:** persist a durable attempt before remote I/O, settle outcomes natively, and reconcile ambiguous outcomes rather than treating them as safely retryable. Do not assume local database transactions can make a remote API call atomic.

Evidence:

- `src-tauri/src/auth/publish.rs:467–499`
- `src/features/approvals/components/publish-linkedin-dialog.tsx:98–115`

### F2 — Medium: quality recovery does not settle linked agent state in the same operation

**Confirmed code gap:** quality failure and stale-run reconciliation update quality runs and attempts, but do not update the linked agent lifecycle records in those operations.

**Risk requiring reproduction:** interrupted quality work can leave quality and agent history inconsistent. The duration and downstream effect of stale agent records need an interruption/resume test, including any other reconciliation paths.

**Recommended fix:** reconcile linked lifecycle records together and verify interruption and resume behavior without creating orphaned or conflicting work.

Evidence: `src-tauri/src/draft_quality.rs:452–489`.

### F3 — Medium: approval loads can overwrite a newer campaign selection

**Confirmed code gap:** asynchronous campaign approval loads set shared state on completion without checking whether the selection is still current. Selection-triggered loading also lacks a local rejection handler.

**Risk requiring reproduction:** a slower campaign A response can replace campaign B's displayed approval data after switching campaigns. This was established by control-flow inspection, not a browser race reproduction.

**Recommended fix:** ignore stale responses and surface current-selection load failures. Verify with deliberately reordered responses and a rejected load.

Evidence: `src/features/approvals/hooks/use-approvals.ts:73–87,121–125`.

### F4 — Browser-only mode cannot persist application data

**Confirmed limitation:** outside Tauri and the injected test adapter, database reads return empty arrays and writes are no-ops. Opening the browser UI is not equivalent to running the desktop app.

**Impact:** browser preview can be misleading if it presents unsupported persistence actions as usable. This is not evidence that native desktop persistence is broken.

**Recommended fix:** visibly identify browser mode as preview-only and disable unsupported actions instead of silently accepting database calls, unless browser persistence becomes an explicit product requirement.

Evidence: `src/lib/db.ts:86–100`.

## Product completeness — spec gaps and intentional boundaries

### Missing production capability

**No production source connector:** the connector registry permits only operator-supplied `local_json`; it does not fetch externally. A compliant production connector is still needed for supported automated source intake.

Evidence: `src/features/source-imports/connectors.ts:3–26`.

### Delivered functionality with deliberate limits

- Autopilot is local planning, not a complete unattended pipeline. It creates local work; scoring and drafting require operator actions. The planner itself does not fetch posts or invoke models.
- Native scheduling operates while Linkgo is running or hidden to the tray, not after the app fully quits.
- LinkedIn publishing and commenting remain human approval-gated. Scraping and arbitrary browser automation are intentionally excluded, not recommended additions.
- LinkedIn commenting and metric refresh depend on the required platform access and scopes; implementation alone does not establish that a user's account has that access.

These boundaries are described in `README.md`, including its current-status and feature-slice sections. They must not be represented as a fully autonomous growth system.

## Unverified areas and follow-up risks

The following were not established by this audit:

- Packaged desktop installation, startup, and real native IPC behavior.
- Real OAuth login, OS credential storage, and live AI-provider calls.
- Live LinkedIn publishing, commenting, and metric refresh.
- End-to-end native scheduler operation and crash recovery.
- Complete current browser UI execution, blocked by the missing Chromium executable.
- Cross-platform runtime behavior, performance, accessibility, or comprehensive security readiness.
- Transaction affinity, rollback, and concurrent behavior of the remaining renderer-managed SQL transactions. Passing the allowlist guard does not prove those properties; dependency-source inspection and real database tests are needed before promoting this risk to a demonstrated failure.

Native tests include database fixtures, but they do not establish all production desktop/database boundaries. Browser tests use injected native mocks for many paths and cannot by themselves certify the shipped desktop integrations.

## Recommended order of work

1. Restore the verification environment and formatting gate without weakening checks; rerun the complete affected checks.
2. Plan and verify publishing attempt persistence and ambiguous-outcome recovery before relying on live external actions.
3. Reproduce and address linked quality-state recovery and stale approval loads.
4. Investigate renderer transaction behavior using installed dependency source and native concurrency/fault tests.
5. Perform a real desktop acceptance flow from campaign creation through approval-gated publishing, using explicitly authorized test accounts and external actions.
6. Add a compliant production source connector when its requirements and platform permissions are settled.

This list is an audit recommendation only. Inspect existing structured Roadmap phases before proposing any new work to avoid duplication. No phase was drafted, updated, or marked Done by saving this report.
